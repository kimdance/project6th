# 90. 参考資料：想定価格帯と価格戦略の比較

- **ドキュメント種別**: 参考資料（上流工程の補助。要件・設計の正式成果物ではない）
- **対象システム（仮称）**: 居酒屋店舗システム（SaaS型） ／ AIネイティブ再構築版
- **作成日**: 2026-09-03
- **ステータス**: ドラフト（検討用のたたき台）
- **関連文書**: `01_system_overview.md`、`02_requirements.md`

> 本書は「フェーズ1の機能を提供する場合、国内でどのくらいの料金が相場か」を整理し、
> あわせて価格戦略・課金モデルの選択肢を比較したものである。番号を 90 番台にしているのは、
> 上流工程の正式成果物（01=概要、02=要件、03=ドメインモデル、04=アーキテクチャ）とは別系統の

---

## 0. 重要な注意

- 本書の金額は**すべて概算・レンジ**であり、2025 年前後に各社が公開していた情報をもとにした
  おおまかな相場観である。SaaS の価格プランは改定が頻繁なため、**競合の最新かつ正確な価格は
  必ず各社公式サイトで確認すること**。
- 為替により変動する海外系サービス（Square 等）の円換算は目安。
- 決済手数料は決済事業者へ支払うものであり、本システムの売上（サブスク収益）とは別勘定。

## 1. 価格を考える前提：フェーズ1の機能セット

`02_requirements.md` のフェーズ1スコープ＝おおむね「予約 ＋ Web予約 ＋ メニュー ＋ 卓・注文
（スタッフ／モバイルオーダー） ＋ 会計POS（現金・PayPay・クレカ・楽天ペイ） ＋ 日次締め・売上日報
＋ シフト・勤怠の基本 ＋ 監査ログ」。

国内の市場区分では、これは **「予約・POS・モバイルオーダー統合型」** に相当する。
（ダッシュボード・AI・在庫・CRM はフェーズ2以降のため、ここでは価格に含めない。）

| カテゴリ | 代表サービス（例） | 月額（1店舗・目安） | 備考 |

| グルメサイト経由の予約送客 | ホットペッパーグルメ 等 | 固定費＋従量 | 送客手数料の目安：ランチ ¥50〜/人、ディナー ¥200/人前後 |
| モバイルオーダー（セルフオーダー） | ダイニー、Okage、Square セルフオーダー | ¥0〜¥20,000 | 単体では ¥10,000〜¥20,000 が中心 |

## 4. コスト負担の内訳（誰が何を払うか）

| 費目 | 支払う人 | 受け取る人 | 区分 |
|------|----------|-----------|------|
| 月額サブスク | 店舗 | 自社（SaaS提供者） | 本システムの主収益 |
| 初期費用・オンボーディング | 店舗 | 自社 | 任意。無料化して導入障壁を下げる選択も |
| 決済手数料 | 店舗 | 決済事業者（PayPay／決済代行） | 通過するだけ。将来アグリゲートするなら別途検討 |
| ハードウェア | 店舗 | 販社／メーカー | 自社で斡旋・レンタルを収益化する余地あり |
| インフラ費・LLM API 費 | 自社 | クラウド／AI ベンダー | 自社の原価。LLM はフェーズ2から発生 |
| サポート人件費 | 自社 | — | 「少人数運用」前提なら価格に織り込む |

## 5. 価格戦略の比較

| 戦略 | 月額（1店舗） | 想定顧客 | メリット | デメリット・リスク |
|------|---------------|----------|----------|--------------------|
| **A. フリーミアム** | ¥0 ＋ 上位 ¥10,000 前後 | 幅広い個人店〜小規模 | 導入障壁が最小。Airレジ／スマレジ／Square と同じ土俵。決済・上位機能で回収 | 無料ユーザーのサポートコスト。有料転換率が読めない。無料層のインフラ負担 |
| **B. 低価格サブスク** | ¥3,000〜¥8,000 | 個人経営・一人運営の居酒屋 | 「競合の半額」で明確に差別化。既存システムの参考コンセプト（一人SaaS）と整合 | 1店舗あたり単価が低く、多数の契約が必要。値上げが難しい |
| **C. 標準サブスク** | ¥12,000〜¥20,000 | 予約もモバイルオーダーも本気で使う店 | 統合価値で正面勝負。粗利を確保しやすい | 無料POSや専用予約サービスとの比較で「高い」と見られやすい。価値訴求が必須 |

**初期リリースの落とし所（たたき台）**：
A と B の中間で、**「無料プラン（会計・予約の基本のみ）＋ スタンダード ¥6,000〜¥9,000／月（モバイルオーダー・
シフト・売上日報・複数ユーザーを含む）」** の2段構成。フェーズ2でダッシュボード・AI・在庫を上位プラン
（¥15,000〜¥20,000／月）として追加する余地を残す。

## 6. 課金モデルの選択肢

| モデル | 内容 | 向き・不向き |
|--------|------|--------------|
| 店舗（拠点）課金 | 1店舗あたり定額 | 最も分かりやすい。個人店中心なら第一候補 |
| ユーザー数課金 | ログインユーザー数に応じて加算 | スタッフ数の多い店で高くなり、居酒屋には不評になりがち。採用するなら「◯人まで込み、超過分のみ加算」 |
| 従量課金 | 会計件数・予約件数・モバイルオーダー件数に連動 | 繁忙店から多く取れるが、店側が予測しづらく敬遠されやすい |
| 決済連動 | 決済手数料に上乗せ（サブスクを無料/低額に） | 無料POS勢の戦い方。自社が決済に深く関与する必要があり、フェーズ1では重い |
| ハイブリッド | 低い店舗定額 ＋ 一部機能を従量（例：SMS通知、モバイルオーダー件数） | 現実的。基本は定額、コストが読める範囲で従量を足す |

**推奨**：フェーズ1は **店舗定額（プラン制）** をベースにし、外部コストが直接乗る要素
（SMS 送信など）だけ実費従量、とする。

## 7. 価格に効く自社コスト要因（フェーズ別）

- **フェーズ1**：インフラ費（サーバ・DB・帯域）、メール／SMS 送信費、サポート人件費、決済連携の開発・保守。
  LLM 費は発生しない。→ 低めの価格でも粗利を確保しやすい。
- **フェーズ2以降**：LLM API 利用料（AIアシスタント・自然言語レポート・需要予測等）、
  ベクトル検索のインフラ。→ AI を含む上位プランは、利用量に応じたコストを価格に織り込む必要がある
  （`01_system_overview.md` 6章「コスト」、`02_requirements.md` NFR-18）。

## 8. 検討ステップと未決事項

1. ターゲットの再確認：初期は「個人経営・一人運営の居酒屋」に絞るか（→ 戦略 B 寄り）、
   小規模店全般に広げるか（→ 戦略 A 寄り）。`02_requirements.md` 11章 の論点と連動。
2. 無料プランを設けるか。設ける場合の機能線引き（会計・予約のみ／モバイルオーダーは有料 等）。
3. スタンダードプランの価格（¥6,000〜¥9,000 のどこに置くか）と、含める機能の範囲。
4. 初期費用・オンボーディングを有償にするか無償にするか。
5. 課金は店舗定額のみか、SMS 等の実費従量を併用するか。
6. 決済手数料に関与するか（当面は「店舗が各決済事業者と直接契約」＝関与しない、で整合）。
7. フェーズ2の AI 込み上位プランの価格レンジ（LLM コストの見積り後に確定）。
8. 競合各社の**最新の実売価格**を公式サイトで確認し、本書の相場観を更新する。
